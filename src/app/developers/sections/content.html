Quickstart

This guide will get you all set up and ready to use the 4DA API. We'll cover how to get started using one of our API clients and how to make your first API request.

Before you can make requests to the 4DA API, you will need to grab your API key from your dashboard. You find it under Settings → API.

Choose your client

Before making your first API request, you need to pick which API client you will use. In addition to cURL HTTP requests, 4DA offers clients for JavaScript, Python, and PHP.

# cURL is most likely already installed on your machine
curl --version

# Install the 4DA JavaScript SDK
npm install @4da/api --save

# Install the 4DA Python SDK
pip install 4da_api

# Install the 4DA PHP SDK
composer require 4da/sdk

Making your first API request

After picking your preferred client, you are ready to make your first call to the 4DA API. Below, you can see how to send a GET request to the Conversations endpoint.

# cURL
curl -G https://api.4da.dev/v1/conversations \
  -H "Authorization: Bearer {token}" \
  -d limit=10

# JavaScript
import ApiClient from '@4da/api'

const client = new ApiClient(token)

await client.conversations.list()

# Python
from 4da_api import ApiClient

client = ApiClient(token)
client.conversations.list()

SDKs

4DA provides first-party SDKs for popular programming languages to make integration easier.

JavaScript / TypeScript

# Install via npm
npm install @4da/api

# Install via yarn
yarn add @4da/api

# Install via pnpm
pnpm add @4da/api
import { ApiClient } from '@4da/api'

const client = new ApiClient({
  apiKey: 'your-api-key',
  environment: 'production'
})

const conversations = await client.conversations.list({
  limit: 20
})

Python

# Install via pip
pip install 4da-api
from 4da_api import ApiClient

client = ApiClient(
    api_key="your-api-key",
    environment="production"
)

conversations = client.conversations.list(limit=20)

PHP

# Install via Composer
composer require 4da/sdk
use FourDA\Api\ApiClient;

$client = new ApiClient([
    'api_key' => 'your-api-key',
    'environment' => 'production',
]);

$conversations = $client->conversations->list([
    'limit' => 20
]);

Authentication

The 4DA API uses API keys to authenticate requests. You can view and manage your API keys in the developer dashboard.

API Keys

Your API keys carry many privileges, so be sure to keep them secure! Do not share your secret API keys in publicly accessible areas such as GitHub, client-side code, and so forth.

All API requests must be made over HTTPS. Calls made over plain HTTP will fail. API requests without authentication will also fail.

Making authenticated requests

Authentication to the 4DA API is performed via HTTP Bearer Auth. Provide your API key as the bearer token.

curl https://api.4da.dev/v1/conversations \
  -H "Authorization: Bearer sk_live_4da_xxxxxxxxxxxx" \
  -H "Content-Type: application/json"

Key types

  • Live keys (sk_live_) — Used for production requests
  • Test keys (sk_test_) — Used for development and testing
  • Publishable keys (pk_) — Safe to expose in client-side code

Pagination

The 4DA API uses cursor-based pagination. Every list endpoint accepts a limit parameter and returns a cursor for the next page.

Parameters

  • limit — Number of items to return (default: 20, max: 100)
  • cursor — Opaque cursor for pagination

Example

# First page
curl https://api.4da.dev/v1/conversations?limit=20

# Response includes:
{
  "data": [...],
  "pagination": {
    "next_cursor": "eyJpZCI6MTIzfQ==",
    "has_more": true
  }
}

# Next page
curl https://api.4da.dev/v1/conversations?limit=20&cursor=eyJpZCI6MTIzfQ==

Errors

The 4DA API uses standard HTTP status codes to indicate the success or failure of requests.

HTTP Status Codes

  • 200 — Success
  • 400 — Bad Request — The request was malformed
  • 401 — Unauthorized — Invalid or missing API key
  • 403 — Forbidden — Insufficient permissions
  • 404 — Not Found — The requested resource doesn't exist
  • 429 — Too Many Requests — Rate limit exceeded
  • 500 — Internal Server Error — Something went wrong on our end

Error response format

{
  "error": {
    "code": "invalid_request",
    "message": "The request was invalid.",
    "details": [
      {
        "field": "limit",
        "message": "Must be between 1 and 100"
      }
    ]
  }
}

Webhooks

Webhooks allow you to receive real-time notifications when events occur in your 4DA account.

Setting up webhooks

You can configure webhook endpoints in the developer dashboard. Each endpoint can be subscribed to specific event types.

Event types

  • conversation.created — A new conversation was created
  • conversation.updated — A conversation was updated
  • message.received — A new message was received
  • contact.created — A new contact was created
  • contact.updated — A contact was updated

Webhook payload

{
  "id": "evt_1234567890",
  "type": "message.received",
  "created_at": "2026-04-24T12:00:00Z",
  "data": {
    "message_id": "msg_abcdefg",
    "conversation_id": "conv_123456",
    "contact_id": "ct_789012"
  }
}

Verifying webhooks

Each webhook request includes a signature header that you can use to verify the request came from 4DA.

# Verify the signature
const signature = request.headers['x-4da-signature']
const isValid = verifySignature(signature, payload, webhookSecret)

Contacts

The Contact object represents a person or organization that you communicate with through 4DA.

Create a contact

POST /v1/contacts

{
  "name": "John Doe",
  "email": "john@example.com",
  "phone": "+1234567890"
}

List contacts

GET /v1/contacts?limit=20&cursor=

Retrieve a contact

GET /v1/contacts/:id

Update a contact

PATCH /v1/contacts/:id

{
  "name": "Jane Doe"
}

Delete a contact

DELETE /v1/contacts/:id

Conversations

The Conversation object represents a thread of communication between contacts and your team.

Create a conversation

POST /v1/conversations

{
  "contact_id": "ct_123456",
  "title": "Support request"
}

List conversations

GET /v1/conversations?limit=20&status=open

Retrieve a conversation

GET /v1/conversations/:id

Update a conversation

PATCH /v1/conversations/:id

{
  "status": "closed"
}

Messages

The Message object represents a single message within a conversation.

Send a message

POST /v1/conversations/:id/messages

{
  "content": "Hello! How can I help you?",
  "type": "text"
}

List messages

GET /v1/conversations/:id/messages?limit=50

Retrieve a message

GET /v1/conversations/:conversation_id/messages/:id

Groups

The Group object represents a collection of contacts that can be messaged together.

Create a group

POST /v1/groups

{
  "name": "Support Team",
  "contact_ids": ["ct_123", "ct_456"]
}

List groups

GET /v1/groups?limit=20

Retrieve a group

GET /v1/groups/:id

Update a group

PATCH /v1/groups/:id

{
  "name": "Engineering Team"
}

Delete a group

DELETE /v1/groups/:id

Attachments

The Attachment object represents a file that can be associated with a message.

Upload an attachment

POST /v1/attachments
Content-Type: multipart/form-data

{
  "file": <binary file>,
  "filename": "document.pdf"
}

Retrieve an attachment

GET /v1/attachments/:id

Delete an attachment

DELETE /v1/attachments/:id
